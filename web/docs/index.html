PROJECT HANDBOOK · VERSION 1.2.1

Documentation

A field guide to building, exploring, and contributing to akernel.

Getting started·x86 & x86-64
i

Project status. The opt-in make CC=gcc iso target builds an x86-64 Limine boot image for BIOS and UEFI VM testing. Use make iso-zip to create a ZIP and SHA-256 file alongside it. akernel is still a kernel scaffold, not a complete operating system or installer; the legacy ELF targets are unchanged.

01 — BEFORE YOU BEGIN

Build requirements

Both architecture targets use the same C source, with separate assembly entry points and linker scripts. You will need:

  • GNU Make
  • GCC with 32-bit compilation support
  • GNU binutils with i386 and x86-64 ELF linkers
  • NASM
  • For the ISO, curl and xorriso; add zip and sha256sum for the ZIP archive

02 — BUILD BY HOST OPERATING SYSTEM

Step-by-step build guides

Choose the instructions for the computer you are building on. Linux distributions have separate package-manager steps; Windows uses WSL 2, and macOS uses a disposable Linux VM. The optional ISO build requires xorriso and downloads a pinned Limine release with checksum verification.

  • All build guides and safety notes
  • Ubuntu and Debian Linux
  • Fedora Linux
  • Arch Linux
  • Windows 10/11 with WSL 2
  • macOS with an Ubuntu VM
SafetyTest the locally built ISO in a disposable VM only. It is not an installer; never write it to a physical disk or replace your operating system.

The Limine ISO target is separate from the legacy entry points: it uses the Limine protocol, requests an RGB framebuffer, displays the system-information screen, and runs the AASH nightly setup preview. The 32-bit and standard 64-bit ELF targets remain loader-dependent.

07 — PACKAGE STATUS

Packages in this version

The current package code is metadata and interface scaffolding. It is not an installer, package repository, or complete runtime service. The fetch renderer is included in the opt-in Limine boot target; package sources are not part of the default make targets.

pkg/akernel/package.hCommon package descriptor, version comparison, and target compatibility checks.
pkg/akernel/fetch/Text system-information renderer with compact ASCII artwork; a caller-provided writer handles output.
pkg/akernel/aash/Experimental freestanding interpreter for boot-embedded AASH scripts.
pkg/akernel/setup/Non-destructive first-boot preflight screen; disk installation is not implemented.
pkg/akernel/sys/System package descriptor stub; system calls and runtime services are not implemented.
kernel/include/akernel/akPackage.hKernel version, x86/x86-64, freestanding, and ELF target metadata.

Both sample package descriptors require kernel 1.1.0 or newer, freestanding ELF builds, and a supported x86 architecture. These checks do not install or execute packages.

See the package guide for archive verification and experimental descriptor examples, or the OS manual for a VM-first development path.

08 — CONTRIBUTE

Make a contribution

  1. 01

    Fork the repository and clone your fork.

  2. 02

    Create a focused branch, make your changes, and run make.

  3. 03

    Commit the files you changed and push your branch to your fork.

  4. 04

    Open a pull request against oysterzarskyy/akernel.

GITexample workflow

make
git add path/to/changed-files
git commit -m "Describe the change"
git push -u origin my-change

10 — COMMUNITY

Forum API and anonymous accounts

The forum front end is connected to the JSON API in api/server.py. The API assigns a persistent anonymous guest identity using a long-lived HttpOnly cookie. The cookie is not readable by page scripts; the browser sends it automatically with requests. Clearing browser cookies loses access to that anonymous identity, so this is not a recoverable registered account.

GitHub Pages serves static files and cannot run the Python API process. Host the API separately or put it behind a same-origin reverse proxy, then set the akernel-api-base meta value in web/index.html to the API prefix (for example, https://api.example.com/api).

LOCAL APIPython 3, no external packages
python api/server.py
# Open http://127.0.0.1:8787

For a separately hosted site, configure AKERNEL_ALLOWED_ORIGIN to the exact website origin. Cross-site cookies require HTTPS and these settings:

COOKIE SETTINGSHTTPS deployments only
AKERNEL_ALLOWED_ORIGIN=https://your-site.example
AKERNEL_COOKIE_SAMESITE=None
AKERNEL_COOKIE_SECURE=1

The API currently supports anonymous sessions, listing/filtering discussions, creating discussions, reading a discussion with replies, and posting replies. Data is stored in SQLite at api/forum.sqlite3 by default. Back up this database and put the service behind a production HTTPS reverse proxy before exposing it publicly.
